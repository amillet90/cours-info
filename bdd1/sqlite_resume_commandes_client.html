Voici le tableau comparatif complet intégrant MySQL, PostgreSQL et SQLite3 :

Action MySQL (mysql) PostgreSQL (psql) SQLite3 (sqlite3)
Se connecter mysql --user=login --password=secret --host=serveurmysql --database=BDD_login PGPASSWORD="secret" psql --host=serveur --username=login --dbname=BDD_login sqlite3 ma_base.db (fichier local)
Lister les bases SHOW DATABASES; \l .databases (fichiers attachés)
Changer de base USE BDD_login; \c BDD_login .open ma_base.db
Lister les tables SHOW TABLES; \dt .tables
Voir la structure DESCRIBE table; \d table .schema table ou PRAGMA table_info(table);
Structure détaillée SHOW CREATE TABLE table; \d+ table .schema table
Lister les utilisateurs SELECT User FROM mysql.user; \du N/A (pas de gestion d’utilisateurs)
Exécuter un script source fichier.sql; \i fichier.sql .read fichier.sql
Quitter le terminal exit; \q .exit ou .quit

À noter pour SQLite

  • Méta-commandes : Tout comme dans PostgreSQL, les commandes propres au CLI SQLite commencent par un point (.tables, .schema, .read) et n’ont pas besoin de point-virgule à la fin.
  • Fichier local : SQLite n’est pas un serveur client-serveur. Il n’y a donc pas de notion d’hôte (--host), d’utilisateur (--user) ni de mot de passe à fournir lors de la connexion.
